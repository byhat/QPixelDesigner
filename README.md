# QPixelDesigner

A visual UI editor for small pixel displays: ST7735 (128x160), SSD1306
(128x64), ILI9341 (320x240) and any custom size. It shows how an interface
will look on the real screen without the hardware: every pixel is visible
individually and fonts are rendered without antialiasing.

![Layout mode](docs/layout-mode.png)

## Features

- canvas with 1-24x zoom and a pixel grid (8-pixel group boundaries highlighted);
- elements: rectangle (with rounded corners), ellipse, line, text;
- multiple selection: Shift+click, rubber band, Ctrl+A;
- groups (Ctrl+G / Ctrl+Shift+G) — grouped elements move together;
- layers: drag rows in the list, PgUp/PgDn, reordering from the context menu;
- always-on-top 1:1 preview window;
- status bar eyedropper: cursor position and pixel color;
- JSON projects (`*.pixui.json`), PNG export;
- RGB565 C header export (xxd -i format) with optional contrast,
  saturation and brightness correction;
- QML mode: a syntax-highlighted editor with a live render of the scene
  on the pixel screen.

## QML mode

![QML mode](docs/qml-mode.png)

The "QML mode" button opens a project workspace: a file tree, a tabbed code
editor with QML syntax highlighting, and the rendering as a second central
tab — "Layout" shows the layout editor canvas, "QML screen" shows the
rendered scene on the same pixel grid; switching tabs switches modes.

- **Open folder…** (or drag a folder / .qml files onto the panel) points the
  panel at an existing QML project on disk; files are edited in place.
- Files in the project reference each other by file name (`MenuButton.qml`
  becomes the `MenuButton` type), including subdirectories via
  `import "subdir"`; every reload re-reads them all.
- **qrc resources**: .qrc files of the project are parsed and qrc:/ URLs are
  resolved to project files (prefixes and aliases included), so
  `source: "qrc:/gfx/banner.png"` works exactly like in a compiled Qt
  project — no path rewriting when moving to real hardware.
- The root scene defaults to `main.qml` (or the first .qml file); any file
  can be set as root from the tree context menu.
- Typing auto-saves the active file to disk after 0.6 s and reloads the
  scene; F5 reloads without waiting. Tab titles show unsaved edits.
- QML errors and warnings are logged with file/line/column; on error the
  canvas keeps the last good frame.
- The "New file" button creates a .qml file in the project folder.

The code editor follows Qt Creator basics:

| Input | Behavior |
|---|---|
| Enter | keeps the indent, one level deeper after `{`; opens a block between `{` and `}` |
| `{ ( [ " '` | inserts the matching pair; a selection gets wrapped |
| `} ) ] " '` | steps over the closing character |
| `}` at line start | dedents the line |
| Backspace | deletes an empty pair |
| Tab / Shift+Tab | indents / dedents lines by 4 spaces (selection-aware) |
| Ctrl+/ | toggles `//` comments |

Qt Quick antialiasing renders small text in gray, so frames are
post-processed (combo box in the QML panel):

| Mode | Action |
|---|---|
| Gray -> B/W | gray pixels become black/white, colors preserved |
| Full 1-bit | whole frame in black and white (monochrome emulation) |
| No processing | frame unchanged |

Using `renderType: Text.NativeRendering` in scene code is recommended —
native font rendering instead of distance-field.

The .pixui.json project stores the folder path and entry file
(`"qmlDir"`, `"qmlEntry"`); QML sources stay on disk next to it.

## RGB565 export

The "RGB565 C array…" button replaces the chain

```bash
ffmpeg -i icon.png -f rawvideo -pix_fmt rgb565be icon.raw
xxd -i icon.raw > image_data.h
```

The render comes straight from the layout at screen resolution; contrast,
saturation and brightness (the `eq` filter equivalent) and the byte order
(`rgb565be` or `rgb565le`) are configurable. The result is a header with an
`unsigned char` array and a `<name>_len` variable.

## Examples

- [examples/Display_ESP32](examples/Display_ESP32) — Arduino sketch that
  draws a 128x160 RGB565 image on an ST7735 SPI TFT using an ESP32;
  `image_data.h` is generated by this editor's RGB565 export.

## Building

Dependencies: CMake >= 3.16, a C++17 compiler, Qt 6.2+ (Widgets, Qml,
Quick, QuickWidgets modules).

Arch Linux:

```bash
sudo pacman -S --needed qt6-base qt6-declarative cmake gcc
```

Debian/Ubuntu:

```bash
sudo apt install build-essential cmake qt6-base-dev qt6-declarative-dev
```

Build and run:

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/QPixelDesigner
```

## Controls

| Action | Input |
|---|---|
| Zoom | toolbar spinbox, Ctrl+mouse wheel |
| Select | click; Shift+click to add/remove; rubber band; Ctrl+A |
| Move | drag, arrow keys (1 px), Shift+arrows (5 px) |
| Resize | drag a selection corner handle (except text) |
| Layers | drag in the list, PgUp/PgDn, context menu |
| Group | Ctrl+G, Ctrl+Shift+G |
| Duplicate | Ctrl+D |
| Delete | Delete, Backspace |

## Project format

Projects are stored as JSON:

```json
{
  "mode": "layout",
  "screen": { "width": 128, "height": 160, "background": "#ffffffff" },
  "elements": [
    {
      "kind": "rect",
      "name": "item1",
      "rect": [6, 30, 116, 20],
      "fill": "#ff000000",
      "stroke": "#ff000000",
      "filled": false,
      "radius": 4,
      "group": 1
    }
  ]
}
```

For QML mode `"mode": "qml"` and the scene code goes into the `"qml"` field.
